SwiftUI 中使用图片最简单的方式是把图片拖进XCode 的 Assets.xcassets 中。然后使用 `Image("imageName")` 就可以加载图片了。

如果图片没有放在 `Assets.xcassets` 中，而是作为普通文件打包在自定义 Bundle（如 `MyAssets.bundle`）里时，不能使用 `Image("imageName")` 这种 SwiftUI 的 Assets Catalog 方式加载。

你需要手动从 Bundle 路径创建 `UIImage`，再转换为 `Image`。

注意：这里如果要把一个文件夹放进 App 中并且保持目录结构，直接拖进 XCode 中是不行的，因为直接拖入项目的资源文件会放在根目录下，任何目录都会扁平化。保存目录结构按照以下步骤：在 Project Navigator 点击你想项目名字，出现 XXX.xcodeproject 标签页，在 TARGETS 一栏下选择你的项目名称，找到右侧的 Build Phases 标签页，找到 Copy Bundle Resources，点击下面的 + 号，在弹出的对话框中点击 Add Other... 按钮，选择你的药药添加的文件夹，弹出对话框 Choose options for adding these files，选中 Destination: Copy items if needed。在 Add folders 中选中 Create folder references。

## 从 Bundle 加载图片并显示

### 步骤 1：获取图片在 Bundle 中的路径或 URL

```swift
// 假设你的 bundle 已经加载
guard let webBundle = Bundle.main.url(forResource: "MyAssets", withExtension: "bundle"),
    let bundle = Bundle(url: webBundle) 
else {
    print("无法找到 MyAssets.bundle")
    return
}

// 获取图片路径（例如 MyAssets/images/cover.jpg）
guard let imagePath = bundle.path(
    forResource: "cover",
    ofType: "jpg", 
    inDirectory: "images"
) else {
    print("无法找到 cover.jpg")
    return
}
```

### 步骤 2：创建 `UIImage`

```swift
// 方式一：直接从路径创建 UIImage
guard let uiImage = UIImage(contentsOfFile: imagePath) else {
    print("无法加载图片")
    return
}
```

### 步骤 3：转换为 SwiftUI 的 `Image`

```swift
import SwiftUI

// 将 UIImage 转换为 SwiftUI Image
let image = Image(uiImage: uiImage)
```

### 完整示例

```swift
func loadImageFromBundle(named: String, type: String = "png", subdirectory: String? = nil) -> Image? {
    guard let bundleURL = Bundle.main.url(forResource: "MyAssets", withExtension: "bundle"),
          let bundle = Bundle(url: bundleURL) else {
        return nil
    }
    
    guard let imagePath = bundle.path(forResource: named, ofType: type, inDirectory: subdirectory) else {
        return nil
    }
    
    guard let uiImage = UIImage(contentsOfFile: imagePath) else {
        return nil
    }
    
    return Image(uiImage: uiImage)
}
```

### 使用方式

```swift
var body: some View {
    VStack {
        if let image = loadImageFromBundle(named: "cover", type: "jpg", subdirectory: "images") {
            image
                .resizable()
                .scaledToFit()
                .frame(height: 200)
        } else {
            Text("图片加载失败")
        }
    }
}
```

## 解析图片路径

对于静态、基本不会改变的图片，放进 Assets.xcassets 中，使用 `Image("imageName")` 就可以加载图片了。当需要从 Bundle 中加载图片时，很可能你得到的路径也不是固定的。例如，你得到图片路径可能是 `/images/cover.jpg`，假设在 bundle 中打包的图片路径是 `MyAssets/images/cover.png`，为了从 `WebAssets.bundle` 中正确加载图片资源，你需要先解析这个字符串以提取文件名（不包括扩展名）、文件类型（扩展名）以及子目录信息。

### 1. 解析路径字符串

首先，我们需要将路径字符串拆分为文件名（不含扩展名）、文件类型（扩展名）和子目录。

```swift
struct ParsedPath {
    let name: String
    let suffix: String
    let directory: String?
}

func parseImagePath(_ path: String) -> ParsedPath {
    let url = URL(fileURLWithPath: path)
    
    let name = url.deletingPathExtension().lastPathComponent
    let type = url.pathExtension
    
    // 获取目录部分并清理前后可能存在的斜杠
    var directory = url.deletingLastPathComponent().path()
    // 移除开头和结尾的斜杠
    if directory.hasPrefix("/") {
        directory.remove(at: directory.startIndex)
    }
    if directory.hasSuffix("/") {
        directory.remove(at: directory.index(before: directory.endIndex))
    }
    
    return ParsedPath(
        name: name,
        suffix: type,
        directory: directory.isEmpty ? nil : directory,
    )
}
```

### 2. 根据解析结果构建 imagePath 并加载图片

接下来，使用上面得到的信息来构建正确的 imagePath 并加载图片。

```swift
func loadImageFromWebAssetsBundle(path: String) -> UIImage? {
    let parsedResult = parseImagePath(path)
    
    guard let webAssetsBundleURL = Bundle.main.url(forResource: "WebAssets", withExtension: "bundle"),
          let bundle = Bundle(url: webAssetsBundleURL) else {
        print("无法找到 WebAssets.bundle")
        return nil
    }
    
    guard let imagePath = bundle.path(forResource: parsedResult.name, ofType: parsedResult.type, inDirectory: parsedResult.directory) else {
        print("无法找到指定的图片资源 \(parsedResult.name).\(parsedResult.type)")
        return nil
    }
    
    guard let image = UIImage(contentsOfFile: imagePath) else {
        print("无法加载图片 \(imagePath)")
        return nil
    }
    
    return image
}

// 使用示例

```

如果图片因各种原因加载失败，可以显示一个占位图或者错误信息之类的视图，例如：

```swift
struct BundleImage: View {
    let imagePath: String // 例如 "/images/exercise/triangle-inequality-theorem--ex-10.png"
    let placeholder: Image // 可选：自定义占位图
    
    init(_ imagePath: String, placeholder: Image = Image(systemName: "photo")) {
        self.imagePath = imagePath
        self.placeholder = placeholder
    }
    
    var body: some View {
        Group {
            if let loadedImage = loadImage(from: imagePath) {
                loadedImage
                    .resizable()
                    .scaledToFit()
            } else {
                placeholder
                    .resizable()
                    .scaledToFit()
                    .foregroundColor(.gray)
                    .frame(maxWidth: 100, maxHeight: 100)
                    .overlay(
                        Text("图片加载失败")
                            .font(.caption)
                            .foregroundColor(.red)
                            .padding(4),
                        alignment: .bottom
                    )
            }
        }
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .background(Color(.systemBackground))
    }
    
    private func loadImage(from path: String) -> Image? {
        let parsed = parseImagePath(path)
        
        guard let bundleURL = Bundle.main.url(forResource: "MyAssets", withExtension: "bundle"),
              let bundle = Bundle(url: bundleURL) else {
            return nil
        }
        
        guard let imagePath = bundle.path(
            forResource: parsed.name,
            ofType: parsed.type,
            inDirectory: parsed.directory
            ),
            let uiImage = UIImage(contentsOfFile: imagePath) else {
            return nil
        }
        
        return Image(uiImage: uiImage)
    }
}
```

## 使用矢量图片

上述方法加载的png、jpg图片，可能不适合是视网膜屏幕上显示，我们可以改用矢量图，不过 SwiftUI 默认并不支持加载 SVG，需要使用第三方库如 `SVGView`。不过 SwiftUI 支持加载 PDF，所以也可以把 SVG转换成独立的 PDF，当作图片来显示。

iOS 支持直接从 Bundle 加载 PDF 文件作为“矢量图像”显示，系统会自动按分辨率渲染为位图（如 @1x, @2x, @3x）。这是 Apple 推荐的替代 SVG 的官方方案，广泛用于图标、Logo 等需要高清缩放的场景。如果你把一个 PDF 图片拖进 Assets.xcassets 文件夹，直接当作图片使用 `Image` 就可以显示了。不过如果要想像上面一样从你自己的创建的文件夹中加载，则需要多做一些工作。

如果把前面的函数 `laodImageFromBundle` 做简单的修改，例如：

```swift
func loadImageFromBundle(path: String) -> Image? {
    let parsedResult = parseImagePath(path)
    
    guard let assetsURL = Bundle.main.url(forResource: "MyAssets", withExtension: "bundle"),
        let bundle = Bundle(url: assetsURL) 
    else {
        print("无法找到 MyAssets.bundle")
        return nil
    }
    
    guard let url = bundle.url(
        forResource: parsedResult.name,
        withExtension: "pdf", 
        subdirectory: parsedResult.directory
    ), 
    let data = try? Date(contentsOf: url),
    let uiImage = UIImage(data: data, scale: 0.0) else {
        print("无法加载图片 \(parsedResult.name).\(parsedResult.type)")
        return nil
    }
    
    return Image(uiImage: uiImage)
}
```

可能无法显示PDF。但是如果直接拖进 `Assets.xcassets` 是可以显示的。

当你把 PDF 拖入 Assets.xcassets 时，Xcode 会：

* 预处理 PDF：提取矢量路径，标准化坐标系
* 生成 .car 文件：一种优化的资源容器
* 嵌入渲染元数据：告诉系统“这是一个矢量图”
* 自动处理 scale 和分辨率

而手动加载的是“原始 PDF”，系统需要在运行时解析，对 PDF 结构更敏感

### 解决方案

绕过 `UIImage(data:scale:0.0)`，用 `UIGraphicsImageRenderer` 手动渲染，完全控制渲染过程，兼容所有 PDF。

```swift
func loadPdfFromBundle(from path: String) -> Image? {
    let parsedResult = TextUtils.parseImagePath(path)
    print("Parsed: $parsedResult)")
    
    guard let assetsURL = Bundle.main.url(forResource: "MyAssets", withExtension: "bundle"),
        let bundle = Bundle(url: assetsURL) 
    else {
        print("无法找到 MyAssets.bundle")
        return nil
    }
    
    guard let url = bundle.url(
        forResource: parsedResult.name,
        withExtension: "pdf",
        subdirectory: parsedResult.directory
    ) else {
        print("URL not found")
        return nil
    }
    
    print("✅ URL: $url)")
    
    guard let data = try? Data(contentsOf: url),
          let provider = CGDataProvider(data: data as CFData),
          let document = CGPDFDocument(provider),
          let page = document.page(at: 1)
    else {
        print("❌ Failed to load PDF document")
        return nil
    }
    
    // 获取 PDF 原始尺寸（如 72dpi 下的宽高）
    let pdfRect = page.getBoxRect(.mediaBox)
    let pdfSize = pdfRect.size
    
    // 👇 关键：设置目标渲染尺寸（可根据需要调整）
    let targetSize = CGSize(width: 300, height: 150) // 逻辑点
    
    // 创建高清渲染器（自动使用 @2x/@3x 分辨率）
    let renderer = UIGraphicsImageRenderer(size: targetSize, 
        format: UIGraphicsImageRendererFormat.preferred())
    
    let image = renderer.image { ctx in
        // 可选：白色背景
        ctx.cgContext.setFillColor(UIColor.systemBackground.cgColor)
        ctx.cgContext.fill(CGRect(origin: .zero, size: targetSize))
        
        // 计算缩放比例，保持宽高比
        let scale = min(targetSize.width / pdfSize.width, 
                       targetSize.height / pdfSize.height)
        
        // 居中
        let x = (targetSize.width - pdfSize.width * scale) / 2
        let y = (targetSize.height - pdfSize.height * scale) / 2
        
        // 应用变换
        ctx.cgContext.translateBy(x: x, y: y)
        ctx.cgContext.scaleBy(x: scale, y: scale)
        
        // 👉 翻转 Y 轴（PDF 坐标系 Y 向上，UIKit 向下）
        ctx.cgContext.translateBy(x: 0, y: pdfSize.height)
        ctx.cgContext.scaleBy(x: 1, y: -1)
        
        // 绘制 PDF 页面
        ctx.cgContext.drawPDFPage(page)
    }
    
    // 返回 SwiftUI Image
    return Image(uiImage: image)
}
```

### targetSize 是什么？

它是 `UIGraphicsImageRenderer` 的“画布大小”

```swift
let targetSize = CGSize(width: 300, height: 150)
let renderer = UIGraphicsImageRenderer(size: targetSize)
```

* 单位是 **points**（不是 pixels！）
* 表示：你希望这个图片在界面中“逻辑上”占据多大空间
* 最终生成的 `UIImage` 的 `.size` 就是 `(300, 150)` points

这决定了 SwiftUI 中 `Image` 的默认布局尺寸

它如何影响屏幕显示？

| 设备 | 屏幕 scale | 实际渲染分辨率 | 显示效果 |
|------|------------|----------------|--------|
| iPhone SE (2nd) | @2x | `600 x 300` pixels | 清晰 |
| iPhone 15 Pro | @3x | `900 x 450` pixels | 更清晰 |
| iPad Pro | @2x | `600 x 300` pixels | 同上 |

### 如何选择合适的 `targetSize`？

推荐根据内容语义设置

| 场景 | 建议 `targetSize` |
|------|------------------|
| 数学公式（行内） | `width: 100~200`, `height: 30~50` |
| 独立公式（居中） | `width: 200~400`, `height: 80~120` |
| 图表/插图 | `width: 300~600`, `height: 200~400` |

不要设得太小或太大

* `width: 10` → 可能看不清
* `width: 2000` → 浪费内存，滚动卡顿

### targetSize 会影响图片的最终显示比例吗?

代码使用 `min(scaleX, scaleY)` 会严格保持原始 PDF 的宽高比，不会压扁或拉宽。

```swift
let scale = min(targetSize.width / pdfSize.width, 
               targetSize.height / pdfSize.height)
```

#### 工作原理

假设：

* PDF 原始尺寸：`100 x 50`（宽高比 2:1）
* 目标画布：`300 x 150`

计算：

* `scaleX = 300 / 100 = 3.0`
* `scaleY = 150 / 50 = 3.0`
* `scale = min(3.0, 3.0) = 3.0`

等比放大 3 倍，完美填充，无变形

#### 如果目标画布比例不同

假设：

* PDF：`100 x 50`（宽高比 2:1）
* 目标：`300 x 100`（宽高比 3:1）

计算：

* `scaleX = 300 / 100 = 3.0`
* `scaleY = 100 / 50 = 2.0`
* `scale = min(3.0, 2.0) = 2.0`

使用 `scale = 2.0` 放大：

* 实际绘制宽度：`100 * 2 = 200`（小于 300）
* 实际绘制高度：`50 * 2 = 100`（等于 100）

结果：

* 图像**保持原始比例**
* 两侧有空白（`300 - 200 = 100pt` 空白）
