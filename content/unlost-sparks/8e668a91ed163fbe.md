本系列是我尝试移植 Goldmark 到 Python 时的笔记，虽然最后觉得问题太多，放弃了移植，但是这些笔记也许对解析器设计有些参考价值。

---

Goldmark 的入口文件是根目录下的 `markdown.go`。这里可以看到 Goldmark 提供的丰富的配置选项。

这里使用的配置方式本身值得解释一下，这里用了大量样板代码，其实只是为了解决 Go 的一个弱点：函数参数缺少命名参数功能。

留给用户自定义的地方其实主要就两处，一个是初始化解析器时针对解析器配置，一个是解析时用的上下文。

首先看下入口函数是怎么调用的：

```go
var defaultMarkdown = New()

func Convert(source []byte, w io.Writer, opts ...parser.ParseOption) error {
	return defaultMarkdown.Convert(source, w, opts...)
}
```

Convert 是 Markdown 接口的方法：

```go
type Markdown interface {
	Convert(source []byte, writer io.Writer, opts ...parser.ParseOption) error

	Parser() parser.Parser

	SetParser(parser.Parser)

	Renderer() renderer.Renderer

	SetRenderer(renderer.Renderer)
}
```

然后有一个默认实现：

```go
type markdown struct {
	parser     parser.Parser
	renderer   renderer.Renderer
	extensions []Extender
}

func (m *markdown) Convert(source []byte, writer io.Writer, opts ...parser.ParseOption) error {
	reader := text.NewReader(source)
	doc := m.parser.Parse(reader, opts...)
	return m.renderer.Render(writer, source, doc)
}

func New(options ...Option) Markdown {
	md := &markdown{
		parser:     DefaultParser(),
		renderer:   DefaultRenderer(),
		extensions: []Extender{},
	}
	for _, opt := range options {
		opt(md)
	}
	for _, e := range md.extensions {
		e.Extend(md)
	}
	return md
}
```

但是这样做有必要吗？你需要自定义一个 Markdown 实现吗？

这里我们看到了两处配置：`Option` 和 `parser.ParseOption`。`Option` 就定义在当前文件中：

```go
type Option func(*markdown)

// WithExtensions adds extensions.
func WithExtensions(ext ...Extender) Option {
	return func(m *markdown) {
		m.extensions = append(m.extensions, ext...)
	}
}

// WithParser allows you to override the default parser.
func WithParser(p parser.Parser) Option {
	return func(m *markdown) {
		m.parser = p
	}
}

// WithParserOptions applies options for the parser.
func WithParserOptions(opts ...parser.Option) Option {
	return func(m *markdown) {
		m.parser.AddOptions(opts...)
	}
}

// WithRenderer allows you to override the default renderer.
func WithRenderer(r renderer.Renderer) Option {
	return func(m *markdown) {
		m.renderer = r
	}
}

// WithRendererOptions applies options for the renderer.
func WithRendererOptions(opts ...renderer.Option) Option {
	return func(m *markdown) {
		m.renderer.AddOptions(opts...)
	}
}
```

这一堆 `WithXXX` 函数在做什么？它们就一个目的：让你自定义 `markdown` 这个结构体上的字段。在其他语言中，更常见的做法是暴露构造函数，通过构造函数的参数和默认值来设置。这一堆 WithXXX 函数，大概就是扮演了命名参数的作用。

- `WithExtensions` 允许你添加扩展
- `WithParser` 允许使用自定义的解析器
- `WithParserOptions` 配置 `parser` 的字段，接下来会下面分析。

注意，parser 包中也定义过一个叫 `Option` 的结构体，和这个 Option 不是一回事，大概作者是在找不到合适的词汇来命名了。

如果在移植到 Python 中，需要这些东西吗？说实话，在 Python 中照抄还是很难的，因为找不到这么绕着写的理由，注意这里省略了一些配置：

```python
class Extension(ABC):
    @abstractmethod
    def extend(self, md: Markdown):
        pass

def default_parser() -> Parser:
    return Parser(
        block_parsers=default_block_parsers(),
        inline_parsers=default_inline_parsers(),
        paragraph_transformers=default_paragraph_transformers(),
    )


class Markdown:
    def __init__(
        self, 
        parser: Parser | None = None,
        extensions: List[Extension] | None = None
    ):
        self._parser: Parser = parser or default_parser()
        self._extensions: List[Extension] = []

        if extensions:
            self._extensions.extend(extensions)

    def convert(self, source: str, context: Context | None = None) -> str:
        reader = Reader(source)
        doc = self._parser.parse(reader, context=context)
        return  ''
```

## 针对解析器的配置：Config

默认解析器有很多字段：

```go
type parser struct {
	options               map[OptionName]any
	blockParsers          [256][]BlockParser
	freeBlockParsers      []BlockParser
	inlineParsers         [256][]InlineParser
	closeBlockers         []CloseBlocker
	paragraphTransformers []ParagraphTransformer
	astTransformers       []ASTTransformer
	escapedSpace          bool
	config                *Config
	initSync              sync.Once
}

func NewParser(options ...Option) Parser {
	config := NewConfig()
	for _, opt := range options {
		opt.SetParserOption(config)
	}

	p := &parser{
		options: map[OptionName]any{},
		config:  config,
	}

	return p
}
```

`options` 其实就是在配置 `Config` 这个对象，然后 `Config` 再把它持有的字段转移到 `parser` 上。

`Config` 结构体本身就是配置解析器的，而 `Config` 本身就是一个配置，所以 `options ...Option` 这个参数就像一个套娃，为了配置 `parser` 而设计了 `Config`，又为了配置 `Config` 本身，设计了 `Option` 接口。其实还可继续套下去，为了配置 `Option` 而创建一个 `Option2` 的接口，这个游戏可以无限玩下去。

我们看下这个套娃游戏到底是怎么玩的：

```go
type Config struct {
	Options               map[OptionName]any
	BlockParsers          util.PrioritizedSlice
	InlineParsers         util.PrioritizedSlice
	ParagraphTransformers util.PrioritizedSlice
	ASTTransformers       util.PrioritizedSlice
	EscapedSpace          bool
}
```

注意，`Config` 本质上只是把 `parser` 中需要自定义的字段重复了一遍。

然后又为了允许配置 `Config` 的每个字段，专门设计了一个接口：

```go
type Option interface {
	SetParserOption(*Config)
}
```

然后针对每个字段设计了一个类来实现该接口，目的只是为了能够配置某个具体的字段，首先是 `Options` 中的具体字段：

```go
type OptionName string

const optAttribute OptionName = "Attribute"

type withAttribute struct {
}

func (o *withAttribute) SetParserOption(c *Config) {
	c.Options[optAttribute] = true
}

func WithAttribute() Option {
	return &withAttribute{}
}
```

其实只是为了在 `Options` 中设置一个字段：`Options['Attribute'] = true`。

同时还提供了配置 `Options` 任何字段的选项：

```go
type withOption struct {
	name  OptionName
	value any
}

func (o *withOption) SetParserOption(c *Config) {
	c.Options[o.name] = o.value
}

func WithOption(name OptionName, value any) Option {
	return &withOption{name, value}
}
```

接下来配置 `BlockParser` 字段

```go
type withBlockParsers struct {

func (o *withBlockParsers) SetParserOption(c *Config) {
```

如果要把这个 `Config` 和 `Option` 结构移植到 Python，其实就是两个个简单的 dataclass

```python
@dataclass(slots=True)
class Config:
    options: Dict[str, Any] = field(default_factory=dict)

    block_parsers: List[WeightedBlockParser] = field(default_factory=list)
    inline_parsers: List[WeightedInlineParser] = field(default_factory=list)

    paragraph_transformers: List[WeightedBlockParser] = field(default_factory=list)
    ast_transformers: List[WeightedInlineParser] = field(default_factory=list)

    escaped_space: bool = False

@dataclass(slots=True)
class Option:
    attribute: bool = False
    block_parsers: List[WeightedBlockParser] = field(default_factory=list)
    inline_parsers: List[WeightedInlineParser] = field(default_factory=list)
    paragraph_transformers: List[ParagraphTransformer] = field(default_factory=list)
    ast_transformers: List[ASTTransformer] = field(default_factory=list)
    escaped_space: bool = False
    options: Dict[str, Any] = field(default_factory=dict)
```

问题是，`Option` 只是复制了 `Config` 而已，有必要吗？如果采用这种模式，是不是应该继续设计一个 `Option2` 用来配置 `Option`？这样可以让这个自嗨游戏无限递归下去。

## 解析时的 Context 配置

在解析运行时需要传递一个上下文：

```go
func (p *parser) Parse(reader text.Reader, opts ...ParseOption) ast.Node {
	
	c := &ParseConfig{}
	for _, opt := range opts {
		opt(c)
	}
	if c.Context == nil {
		c.Context = NewContext()
	}
	pc := c.Context
	root := ast.NewDocument()
	p.parseBlocks(root, reader, pc)
}
```

`ParseOption` 是一个函数，目的只是它用户自定义数据搬运到一个临时载体上，然后通过这个临时载体传递给目标函数，如果用户没有自定义 Context，就传递默认值。这个功能在用户自定义解析规则时可能需要。依然是通过函数式配置传递参数：

```go
type ParseConfig struct {
	Context Context
}

type ParseOption func(c *ParseConfig)

func WithContext(context Context) ParseOption {
	return func(c *ParseConfig) {
		c.Context = context
	}
}
```

它的作用，只是为了在 `Parse` 开始的时候初始化一个 `Context`，这个结构体保存的是解析时的上下文信息，本身其实就相当于配置信息了。`Context` 是这么定义的：

```go
type parseContext struct {
	store         []any
	ids           IDs
	refs          map[string]Reference
	blockOffset   int
	blockIndent   int
	delimiters    *Delimiter
	lastDelimiter *Delimiter
	openedBlocks  []Block
}
```

但是作为一个私有结构体，又不想让用户直接碰，又需要给用户权限自定义其中的某些字段，于是就用了这一堆东西，只为了实现让用户自定义一个字段：

```go
type ContextConfig struct {
	IDs IDs
}

// An ContextOption is a functional option type for the Context.
type ContextOption func(*ContextConfig)

// WithIDs is a functional option for the Context.
func WithIDs(ids IDs) ContextOption {
	return func(c *ContextConfig) {
		c.IDs = ids
	}
}
```

通过一个闭包，把用户自定义数据挂在到一个中间结构体上，在通过这个中间结构体把数据传递给目标配置结构体。看下它的用法：

```go
func NewContext(options ...ContextOption) Context {
	cfg := &ContextConfig{
		IDs: newIDs(),
	}
	for _, option := range options {
		option(cfg)
	}

	return &parseContext{
		ids:           cfg.IDs,
	}
}
```

为了让用户自定义 `ids` 这个字段，用了两个函数、一个结构体做过过渡。

在 Python 中，这么实现应该就够了：

```python
class ParseContext(Context):

    def __init__(self, *, ids: IDs | None = None):
        self._ids = ids or IDs()
```

## SetOptioner

还有一处配置在这里：

```go
type SetOptioner interface {
	SetOption(name OptionName, value any)
}

func (p *parser) addBlockParser(v util.PrioritizedValue, options map[OptionName]any) {
	bp, ok := v.Value.(BlockParser)
	if !ok {
		panic(fmt.Sprintf("%v is not a BlockParser", v.Value))
	}
	
	so, ok := v.Value.(SetOptioner)
	if ok {
		for oname, ovalue := range options {
			so.SetOption(oname, ovalue)
		}
	}
}
```

在添加具体的解析器的时候，顺便把一些配置传递给解析器，所以这些解析器需要实现 `SetOptioner` 接口。这个结构体的名字也许叫 `ParserOptionSetter` 更合适。

配置解析器其实更应该在解析器初始化的时候就配置好，而不是初始化完成后再通过方法修改。
