Goldmark 中区分了字符和列宽，所以这个计算要弥散在所有的代码中，理解起来就像迷宫一样。我们看下计算列宽的地方。

## `IndentWidth()`

在工具函数中，`IndentWidth()` 也涉及到列宽和字符的计算：

```go
func IndentWidth(bs []byte, currentPos int) (width, pos int) {
	for i := range len(bs) {
		switch bs[i] {
		case ' ':
			width++
			pos++
		case '\t':
			width += TabWidth(currentPos + width)
			pos++
		default:
			return
		}
	}
	return
}
```

这里返回两个值，`width` 显然计算的是列宽，`pos` 呢？我觉得 `pos` 这个名字可能存在误导，显然它计算的是跳过了多少个空格和 tab 字符，所以叫 `spaceCount` 或许更好。

同样，`currentPos` 这个参数也比较模糊，它的使用场景要配合前面讨论的 `LineOffset()`：

```go
w, pos := util.IndentWidth(line, reader.LineOffset())
```

所以 `currentPos` 表示的是当前位置的列数，显然也只能是列数，因为 `TabWidth` 的用处是向前跳过空格，如果不是从行首开始跳，那就需要知道前面的有多少个列才能继续计算。前面我们分析了，列宽每次都需要从行首开始逐字符统计，否则不知道有多少个 tab，所以如果要从行中间某处开始继续往前移动，就需要知道当前在目在这一行中已经行进了多少个列。

## `IndentPosition`

```go
// 缩进至少指定的宽度后，字符在什么位置？多跳了几列？
IndentPosition(line, reader.LineOffset(), 4)

// currentPos 表示当前游标所在的列
// width 指定需要缩进多少列，如果当前位置前面没有空白，则不缩进
func IndentPosition(bs []byte, currentPos, width int) (pos, padding int) {
	return IndentPositionPadding(bs, currentPos, 0, width)
}

func IndentPositionPadding(bs []byte, currentPos, paddingv, width int) (pos, padding int) {
	if width == 0 {
		return 0, paddingv
	}
	w := 0 // 跳过的列宽
	i := 0 // 字符索引
	l := len(bs)
	p := paddingv
	for ; i < l; i++ {
		if p > 0 {
			p--
			w++
			continue
		}
		if bs[i] == '\t' && w < width { // 遇到 tab
			w += TabWidth(currentPos + w) // 加 tab 应该占多少列
		} else if bs[i] == ' ' && w < width {
			w++ // 空格加 1 列
		} else {
			break // 不是空格或 tab 的字符，停止
		}
	}
	if w >= width { // 如果因为 tab 跳过头了
		return i - paddingv, w - width // 返回跳过字符停止索引和多跳过的列数
	}
	return -1, -1
}
```

## 空行处理

Goldmark 在解析块级元素是非常依赖一个方法：`reader.SkipBlankLines()`，这个方法实际调用的是这个函数：

```go
func skipBlankLinesReader(r Reader) (Segment, int, bool) {
	lines := 0
	for {
		line, seg := r.PeekLine()
		if line == nil {
			return seg, lines, false
		}
		if util.IsBlank(line) {
			lines++
			r.AdvanceLine()
		} else {
			return seg, lines, true
		}
	}
}
```

这个函数返回三个值：第一个是当前的索引区间，第二个是跳过的空行数，第三个布尔值表示什么？当 `line == nil` 的时候返回 `false`，出现在什么情况下？一个空行，哪怕只有一个换行户，也不会是 nil，所以只能是什么都没有的时候，那就是到文件末尾了。所以返回 `false` 的时候应该是表示发现了 EOF，那么 true 就表示还有内容需要继续解析。不过我认为不应该在这个地方、依赖这种方式来检查是否读完了文件，而应该有一个专用的、全局标记，比如一个函数 `IsEOF()`。

## BlockReader

这里似乎有个小问题：

```go
func (r *blockReader) Value(seg Segment) []byte {
	line := r.segmentsLength - 1
	
	ret := make([]byte, 0, seg.Stop-seg.Start+1)
	for ; line >= 0; line-- {
		if seg.Start >= r.segments.At(line).Start {
			break
		}
	}
	// 如果 break 没有触发，索引 line 是 -1?
	// fix:
	if line < 0 {
		line = 0
	}

	i := seg.Start
	for ; line < r.segmentsLength; line++ {
		s := r.segments.At(line)
		if i < 0 {
			i = s.Start
		}
		ret = s.ConcatPadding(ret)
		for ; i < seg.Stop && i < s.Stop; i++ {
			ret = append(ret, r.source[i])
		}
		i = -1
		if s.Stop > seg.Stop {
			break
		}
	}
	return ret
}
```

第一个循环如果结束都没有触发 `break` 呢？ `line = -1`，后续直接用就会触发索引越界。
